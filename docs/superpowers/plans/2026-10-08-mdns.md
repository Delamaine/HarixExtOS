# mDNS Hostname + HTTP Service Announcement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The device is reachable on the LAN as `<hostname>.local` (default `harixos-<chipid>`) and advertises its HTTP server as `_http._tcp` while `serve` runs.

**Architecture:** Framework-bundled ESP8266mDNS (LEAmDNS, global `MDNS` instance) is driven directly from `main.cpp` — no wrapper module. One down→up transition detector in `loop()` starts or renews the responder; `serve` hooks add/remove the `_http._tcp` service by handle; a new `settings hostname <name>` subcommand names the device, defaulting to `harixos-<chipid>` resolved at settings load (mqttPrefix precedent).

**Tech Stack:** ESP8266 Arduino core (bundled `ESP8266mDNS`), PlatformIO, LittleFS `/harixos/settings.cfg`.

**Spec:** `docs/superpowers/specs/2026-10-08-mdns-design.md` — the plan argues from the spec; executors read both.

## Global Constraints

- Board/environment/port: NodeMCU v2, `-e nodemcuv2`, COM3 @ 115200 (AGENTS.md).
- Gates: `python -m platformio run -e nodemcuv2` → SUCCESS; `python -m platformio test -e native` → 177 test cases, 177 succeeded.
- LSP errors (`Arduino.h not found`, `String` unknown, etc.) are pre-existing noise — ignore; PlatformIO gates are truth.
- No new `lib_deps` — only the framework's `ESP8266mDNS`.
- No multi-hundred-byte stack locals in `setup()`/`loop()` paths (boot-WDT lesson from the crash-log work: stack pressure broke the TLS update check).
- Exact copy rules (all user-visible strings below are literal): `Usage: settings hostname <name>` / `Settings saved. Hostname: <name>` / `Hostname: <name>` / `mDNS: <name>.local` / `mDNS: start failed.`
- Device harness (pyserial): force reset `ser.rts=True; sleep(0.3); ser.rts=False`; wait ≥30 s for the boot→prompt (Wi-Fi + update check); at idle the prompt emits nothing (needle-timeout = harness artifact); shell echo arrives char-by-char. Pattern: `C:\Users\delam\AppData\Local\Temp\opencode\final_verify.py`.
- PC-side checks run from Windows PowerShell (`Resolve-DnsName`, `curl`/`Invoke-WebRequest`) on the same LAN.
- One commit per task.

## Review Focus

Five inputs/conditions the spec implies that no build-gate exercises; each is pinned to a numbered device check in Task 2 (RF1/RF3/RF4/RF5) or Task 1 (persist):

1. **Wi-Fi down at runtime or boot** — responder must stay dormant: no crash, no error spam, shell stays responsive, name resolves after reconnect → Task 2 Device check 5.
2. **Begin racing DHCP** (`WL_CONNECTED` can precede `gotIP`) — must not announce `0.0.0.0`; the name must resolve to the real IP → Task 2 Device check 1 (assertion: resolved IP equals `wifi ip`).
3. **Rename while the HTTP server is running** — `_http._tcp` must be re-announced under the new name and curl through `<new>.local` must keep working → Task 2 Device check 3.
4. **`serve stop` / restart handle lifecycle** — no stale or duplicated service, handle nulled, re-serve announces again → Task 2 Device check 4.
5. **Memory/stability regression** — three clean reboots, no abnormal line in `info` → `Last reset`, `heap` within ~4 KB of the pre-mDNS reading → Task 2 Device check 6.

- [ ] **Step 2: Transition detector + update in `loop()`**

Insert immediately after `handleSerialInput();` (main.cpp:2566):

```cpp
{
  bool up = (WiFi.status() == WL_CONNECTED && WiFi.localIP() != IPAddress(0, 0, 0, 0));
  if (up && !mdnsWasUp) {
    if (!mdnsStarted) {
      mdnsStarted = MDNS.begin(shellSettings.hostname.c_str());
      if (!mdnsStarted) {
        Serial.println(F("mDNS: start failed."));
      }
    } else {
      MDNS.notifyAPChange();
      MDNS.announce();
    }
  }
  mdnsWasUp = up;
  if (mdnsStarted) {
    MDNS.update();
  }
}
```

(Spec §2 verbatim: first up → `begin`, later ups → renew; the valid-IP check covers RF2. Failure is non-fatal: one line, no retry — `begin` only fails on config-level errors, conflicts resolve async after it.)
